# Методичка участника

Здесь всё, что нужно, чтобы написать свой алгоритм сортировки, проверить его и правильно сдать через Git.

**Твой путь в 8 шагов:**

1. Подготовить окружение
2. Выбрать алгоритм и сообщить в группу
3. Создать файл и написать функцию
4. Подготовить свои тестовые данные
5. Собрать и проверить
6. Проверить на чужих данных
7. Закоммитить и отправить
8. Подготовиться к защите

---

## 1. Подготовка окружения

1. Установи **VS Code** (не Visual Studio).
2. Установи компилятор **g++** (Windows: MinGW / MSYS2, Linux: `sudo apt install g++`, macOS: `xcode-select --install`). Проверка: `g++ --version`.
3. Установи **Git**. Проверка: `git --version`.
4. Один раз настрой имя и почту (чтобы твои коммиты были подписаны тобой):

```
git config --global user.name "Твоё Имя"
git config --global user.email "почта@от.github"
```

5. **Склонируй** репозиторий (не скачивай ZIP!):

```
git clone <ссылка на репозиторий>
cd <папка репозитория>
```

6. Открой папку в VS Code: `File -> Open Folder`.

---

## 2. Выбор алгоритма

1. Выбери алгоритм (пузырьком, вставками, выбором, слиянием, быстрая, пирамидальная, Шелла, подсчётом и т.д.) и **напиши в группу**, какой берёшь. Алгоритмы не должны повторяться.
2. **Не вайбкодь.** Найди описание алгоритма в интернете, разберись и напиши сам. Код от нейросети часто неоптимален, а защищать его придётся тебе.
3. Прежде чем писать код, ответь себе:
   - Как алгоритм работает по шагам?
   - Какая у него сложность в лучшем, среднем и худшем случае?
   - На каких данных он быстрый, а на каких медленный и почему?

## 3. Создание файла и функции

### Именование

Шаблон: `название_сортировки_by_имя`

| Что | Как | Пример для Ивана и быстрой сортировки |
|---|---|---|
| Файл | `название_сортировки_by_имя.cpp` | `quick_sort_by_ivan.cpp` |
| Функция | то же, но **без `_`** | `quicksortbyivan` |

### Правила

- Сигнатура строго такая: `void названиеsortbyимя(vector<int>& a)`.
- Сортируем **по возрастанию**, **прямо в переданном векторе** (ничего не возвращаем).
- **Только `vector`**, без указателей и `new`/`malloc`.
- Если нужен дополнительный массив (например, для сортировки слиянием), создай локальный `vector` внутри функции.
- Вспомогательные функции делай `static`, чтобы их имена не конфликтовали с функциями из чужих файлов.
- **Не трогай `main.cpp` и `sorts.h`.** Если нужны изменения, напиши капитану. Он добавит твою функцию в `sorts.h` и в список алгоритмов в `main.cpp`.
- Пиши понятный код с короткими комментариями. Ты будешь объяснять его на защите.

### Шаблон файла

```cpp
#include "sorts.h"
#include <utility>   // для swap
using namespace std;

// Вспомогательные функции делаем static
static void helper(vector<int>& a) {
    // ...
}

// Главная функция алгоритма
void selectionsortbyivan(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[minIndex]) minIndex = j;
        }
        swap(a[i], a[minIndex]);
    }
}
```

Готовый пример смотри в `bubble_sort_by_captain.cpp` и `quick_sort_by_captain.cpp`.

## 4. Тестовые данные

Нужно **3-4 файла** в папке `data/`. Имена: `имя_best.txt`, `имя_avg.txt`, `имя_worst.txt` (при необходимости `имя_extra.txt`).

**Формат:** целые числа через пробел или с новой строки.

| Файл | Что внутри | Что нужно уметь объяснить |
|---|---|---|
| `best` | данные, на которых **твой** алгоритм быстрее всего | почему здесь так быстро |
| `avg` | типичные данные, обычно случайные | почему результат средний |
| `worst` | данные, на которых **твой** алгоритм медленнее всего | почему здесь так медленно |

Лучший и худший случаи зависят от алгоритма: для пузырька лучший случай это отсортированный массив, а для быстрой сортировки худший случай зависит от выбора опорного элемента. Подумай заранее!

**Размер:** 10 000-50 000 чисел. Для медленных алгоритмов (O(n²)) не бери больше 50 000, иначе программа будет считать минутами. Для быстрых можно больше, чтобы время было заметно.

### Как создать файлы (Python)

```python
import random

n = 20000
best = list(range(n))            # отсортированный
worst = list(range(n, 0, -1))    # по убыванию (подбери под свой алгоритм!)
avg = best[:]
random.shuffle(avg)              # случайный

for name, data in [("best", best), ("avg", avg), ("worst", worst)]:
    with open(f"data/ivan_{name}.txt", "w") as f:
        f.write(" ".join(map(str, data)) + "\n")
```

### Обязательно проверь крайние случаи

Сделай маленькие файлы (или временно проверь вручную) и убедись, что алгоритм не падает на:

- пустом массиве;
- массиве из одного элемента;
- массиве из двух элементов;
- повторяющихся элементах (например, все числа одинаковые);
- отрицательных числах;
- уже отсортированном и обратном массивах.

## 5. Сборка и проверка

Из папки проекта:

```
g++ -O2 -std=c++17 *.cpp -o sorting
./sorting          (Windows: sorting.exe)
```

Появится меню:

```
1. Start training       - запустить все алгоритмы на всех файлах из data/
2. Save data in .txt    - сохранить результаты в results.txt
3. Save data in .excel  - сохранить результаты в results.csv (открывается в Excel)
4. Exit
```

Выбери `1` и смотри на статус:

- **OK** значит, массив отсортирован верно.
- **WRONG** значит, в алгоритме ошибка. Исправляй!

Если программа не собирается, читай первую ошибку в списке: чаще всего причина в ней, остальные ошибки тянутся за ней.

Если программа "зависла", возможно, твой алгоритм бесконечно крутится в цикле или файл слишком большой для O(n²).

## 6. Проверка на чужих данных

Когда твой алгоритм работает на твоих файлах:

1. Получи свежую версию репозитория: `git pull`
2. Пересобери и запусти `1. Start training`: программа сама прогонит твой алгоритм на **всех** файлах из `data/`, включая чужие.
3. Если где-то `WRONG` или программа падает, **исправляй свой алгоритм** (добавь нужные условия и проверки), а не чужие данные.

Частые причины: дубликаты чисел, отрицательные числа, пустой файл, очень глубокая рекурсия на больших данных.

## 7. Коммиты и отправка в репозиторий

### Правила для сообщений коммитов

Формат:

```
тип: краткое описание
```

Тип всегда **строчными буквами** на английском, описание короткое, на английском, в повелительном наклонении ("add", "fix", а не "added", "fixed"). Без точки в конце.

| Тип | Когда использовать | Пример |
|---|---|---|
| `feat` | новый алгоритм или новая функциональность | `feat: add selection sort by ivan` |
| `fix` | исправление ошибки (баги в алгоритме) | `fix: handle duplicates in selection sort` |
| `test` | добавление или изменение тестовых данных | `test: add best, avg and worst data for selection sort` |
| `docs` | комментарии, README, заметки | `docs: add comments to selection sort` |
| `refactor` | улучшение кода без изменения результата | `refactor: simplify swap logic in selection sort` |
| `perf` | ускорение работы алгоритма | `perf: stop early if array is already sorted` |
| `style` | форматирование, отступы, имена | `style: fix indentation in selection sort` |
| `chore` | служебное (.gitignore, сборка) | `chore: update gitignore` |

**Один коммит это одно логическое изменение.** Не пиши коммиты вроде `fix`, `update` и `asdf`, это считается плохой работой с Git.

### Типичная последовательность

```
feat: add selection sort by ivan             <- файл с алгоритмом
test: add best, avg and worst data for ...   <- файлы с данными
fix: handle empty array in selection sort    <- исправления после проверки на чужих данных
docs: add comments to selection sort         <- комментарии
```

### Команды

1. Посмотри, что изменилось: `git status`
2. Добавь **конкретные файлы** (не `git add .`, чтобы не захватить лишнее):

```
git add selection_sort_by_ivan.cpp
```

3. Сделай коммит:

```
git commit -m "feat: add selection sort by ivan"
```

4. Перед отправкой забери чужие изменения:

```
git pull --rebase
```

5. Отправь:

```
git push
```

### Чего нельзя коммитить

- скомпилированную программу (`sorting`, `sorting.exe`);
- `results.csv`, `results.txt`;
- папку `.vscode/`;
- `main.cpp` и `sorts.h` (их меняет только капитан).

(Всё это уже перечислено в `.gitignore`, но проверяй `git status` перед коммитом.)

### Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| `git push` отклонён (rejected) | сделай `git pull --rebase`, потом снова `git push` |
| Конфликт при `pull` | открой файлы с конфликтом, оставь нужное, удали маркеры `<<<<<<<`, `=======`, `>>>>>>>`, затем `git add файл`, `git rebase --continue`; если не получается, пиши капитану |
| Закоммитил не то | пока не сделал `push`: `git reset --soft HEAD~1` отменит последний коммит, изменения останутся |
| Не знаешь, что происходит | `git status` и `git log --oneline` покажут состояние |

## 8. Подготовка к защите

Ты будешь рассказывать **без бумажки** до 5 минут. Надо уметь объяснить свой код построчно.

Передай капитану материал на **2-3 слайда**:

1. Что такое этот алгоритм, как он работает (основные шаги, лучше с маленьким примером).
2. Особенности, преимущества, ограничения и особые случаи.
3. Сложность в лучшем, среднем и худшем случаях, и на каких данных они достигаются.
4. Результаты тестов: время на best, avg и worst, и почему они такие.

Подготовься к вопросам:

- Почему именно эти данные у тебя лучшие и худшие?
- Устойчивая ли у тебя сортировка (stable)? Сколько дополнительной памяти нужно?
- Что будет на пустом массиве, на дубликатах, на отсортированных данных?
- Зачем нужна та или иная строчка в твоём коде?
